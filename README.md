# schedMOC — RTOS Trace Lab

RTOS タスクの端点間処理を可視化する、オフライン対応のシングル HTML モックです。

## 使い方

`index.html` をダウンロードしてブラウザで開いてください。ビルド、依存ライブラリ、サーバーは不要です。ブラウザの管理ポリシーでローカルファイルを開けない場合は、このディレクトリで `python3 -m http.server 8000 --bind 127.0.0.1` を実行してローカルで閲覧できます。

1. 「基本」「位相調整」「高負荷」で条件の違いを比較します。
2. 再生、一時停止、1 ms ステップ、時刻スライダーで CPU とタスクの状態を確認します。
3. 設定値を編集したら「条件を適用して再計算」を押します。再計算まで画面の結果は前の設定のものです。
4. 結果表の「追跡」で入力 ID の処理経路を強調できます。
5. 適用済みの設定を JSON、入力ごとの結果を CSV で保存できます。JSON は記録用です。インポート機能はありません。

グラフと指標は全観測区間の集計、タスク状態は再生位置の表示です。JavaScript が無効でも解説を読めます。ダークモード、動きを減らす設定、印刷に対応します。

## モデル

- 単一 CPU、プリエンプティブ実行、0.1 ms 刻み。切替コストは 0。
- FP は小さい優先度番号順、RM は短周期順、EDF はジョブの絶対期限順。同点はタスク番号順、同一タスクは FIFO。
- 周期起動では、実行開始時の最新の前段完了データを読取り、中断後も保持します。読み飛ばし、重複出力、空データ出力が起こり得ます。
- 前段完了起動ではデータをジョブに保持し、完了時に次段を起動します。T2/T3 の周期・位相は使いません。このモードでは RM を選択できません。
- 端点間時間は、入力の T1 起動から同じ入力の最初の T3 完了までです。入力 ID と時刻を各段へ引き継ぎます。
- 実行時間のばらつきはシード付き一様分布です。起動ジッタ、排他資源、通信、マルチコア、実機 ISR は対象外です。
- 完了入力の端点間期限超過と、タスクの相対期限超過は別に集計します。未到達入力や観測終了時の未完了ジョブも表示します。

初期サンプルでは 200 ms 中の完了入力は 9 件、観測最大遅れは 23 ms、CPU 使用率は 50%。「位相調整」では観測最大遅れは 7 ms です。これらは説明用モデルの結果であり、報告書の例題の再現や理論的な最悪時間の保証ではありません。

## 検証

このクラウド環境では Playwright と `/usr/bin/chromium` が利用できます。

```sh
node tests/verify.cjs
```

検証用にローカル HTTP サーバーを一時起動し、終了時に停止します。既知の実行順、割込み、データ伝播、期限境界、過負荷、乱数再現性、35 通りの設定での CPU・データ整合性、操作、CSV/JSON 保存を確認します。外部ネットワークを遮断した状態でも操作を検証します。画面幅 360/768/1280 px、ダークモード、動きの低減、印刷、JavaScript 無効の表示も確認します。スクリーンショット等はチェックアウト外の `/workspace/scratch/rtos-verification` に出力します。

別の環境では、検証用に Playwright と Chromium が必要です（HTML の実行には不要）。Chromium の場所は `CHROMIUM_PATH` で指定できます。
