HOW IT WORKS

何が端点間の時間を増やすのか

処理時間の合計だけでは、入力から出力までの時間は決まりません。

01 / RELEASE & WAIT

次の起動を待つ時間

周期起動では、前段の処理が終わっても次段がすぐ動くとは限りません。次段の周期と位相を変更すると、データ読取りまでの待ち時間が変わります。「位相調整」と「基本」を比較してみてください。

02 / PREEMPTION

CPU を譲る時間

実行可能なジョブの中から、選択した方式で最優先のものを実行します。より優先されるジョブの到着は実行中の処理を中断します。T4 の負荷を増やすと、他のタスクが待つ様子を確認できます。

03 / END-TO-END

同じデータの経路を追う

入力 ID をデータとともに引き継ぎ、T1 の起動からそのデータの最初の T3 完了までを測ります。周期の違いで同じ入力が複数回出力された場合、最初の出力のみを数えます。

ソフト期限とハード期限

ソフト期限（DLS）は許容する遅れの評価基準、ハード期限（DLH）は超過を許容できない時間制約です。このモックでは超過件数と観測比率を表示します。ソフト超過が許容可能かどうかは、対象システムの要求で決まります。

計算モデルと結果の読み方

端点間時間 = 最初の T3 完了時刻 − 引き継いだ入力の T1 起動時刻

単一 CPU、0.1 ms 刻みの離散時間モデルです。起動・実行・期限は 0.1 ms 単位、同一時刻では前の区間の完了処理 → 周期起動 → 選択 → 実行の順です。コンテキスト切替コストは 0、タスク間の共有データへのアクセスは瞬時とします。

周期起動：T1〜T4 がそれぞれ周期起動します。T2/T3 は最初に CPU を得た時点の前段完了データを読み、プリエンプト後もそのデータを保持します。前段データがまだなければ空データとして完了します。共有バッファは最新値ひとつだけなので、入力を読み飛ばす場合があります。

前段完了起動：T1 と T4 は周期起動、T2/T3 は前段の完了で FIFO ジョブを追加します。受け渡すデータは各ジョブに保持します。このモードの T2/T3 の周期・位相は使いません。RM もこのモードでは選択できません。

選択方式：FP は P が小さい順。RM は周期 T が短い順。EDF はジョブの絶対期限（起動 + D）が早い順。同点はタスク番号、同一タスク内は FIFO です。T4 は通常の周期監視タスクで、実機の ISR を再現するものではありません。

全区間集計：CPU 使用率は実際に実行した刻み数から計算します。入力未到達件数は読み飛ばしと観測終了時点の処理途中を含みます。完了入力だけの期限超過率とは別に、未到達入力のハード期限経過も表示します。タスク相対期限の超過件数は、未完了で期限を過ぎたジョブも含みます。

再現性：ばらつきは説明用の一様分布で、起動ジッタはありません。同じ設定と乱数シードで同じ結果になります。最大値は観測最大値であり、WCRT の理論値ではありません。マルチコア、ネットワーク、排他資源、優先度継承、静的テーブル探索、数学的な保証は対象外です。
